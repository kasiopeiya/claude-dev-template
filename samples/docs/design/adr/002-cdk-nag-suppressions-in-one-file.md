# ADR-002: cdk-nag の抑制を1ファイルに集約してスタック単位で適用する

## 決定（何を選んだか）

cdk-nag の抑制ルールは `test/nagSuppressions.ts` の配列1つに書き、`bin/app.ts` で全 Stack へ `NagSuppressions.addStackSuppressions` として適用する。個別リソースの隣に `addResourceSuppressions` を書かない。

## 採用理由（なぜこれを選んだか）

抑制は「見逃してよいと判断した指摘」の一覧であり、レビューの対象そのものだから。1ファイルに集めれば、抑制が増えたことが差分に必ず現れ、理由も並べて読める。リソースの隣に散らすと、いま全体でいくつ何を抑制しているかを誰も把握できなくなる。

## 検討した代替案（なぜ却下したか）

**決定の軸：cdk-nag の抑制をどこに書くか。**

| 案                           | 内容                                                | 却下理由                                                                                             |
| ---------------------------- | --------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| リソース単位に書く           | 対象リソースの隣で `addResourceSuppressions` を呼ぶ | 抑制の範囲は狭まるが、総数がコード全体に散ってレビューで数えられない。この規模では把握しやすさを取る |
| ルールをそもそも有効にしない | `AwsSolutionsChecks` を外し、指摘が出ないようにする | 指摘が消えるだけで、なぜ許容したのかの記録も消える                                                   |
