# ADR-013: レビュー系 subagent を、問いの種類で束ねたレンズごとに並列で走らせる

## 決定（何を選んだか）

1体の subagent が取りこぼすレビューは、観点一覧の観点を**対象に向ける問いの種類**（疑って読む／攻撃者の目で読む／規約と見比べる など）で束ねたレンズに分け、レンズごとに subagent を並列で起動する。1回の起動には1つの問いだけを持たせる。

分けるかどうかは、1体の取りこぼしで決める。既定は1体のままで、欠陥を仕込んだ対象で1体が取りこぼしたとき、または実運用で見落としの実例があるときだけ分ける。

## 採用理由（なぜこれを選んだか）

AI は目的を1つに絞ったほうが深く探す。1体に全観点を持たせると、一番見つけたい欠陥（`/code-review` ならバグ）を探す注意が、規約との照合などの別の問いに取られる。

分けると、起動の回数と費用はレンズの数だけ確実に増える。一方、見落としが減る効果は、1体が取りこぼさない限り測れない。だから費用を払うのは、1体の取りこぼしという事実があるときに限る。

## 検討した代替案（なぜ却下したか）

**決定の軸：レビューの観点を、subagent の起動へどう割り振るか。**

| 案                                                     | 内容                                                                                | 却下理由                                                                                                                                                        |
| ------------------------------------------------------ | ----------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| いつも1体で全観点を見る                                | 取りこぼしが出ても分けない                                                          | 中心の問いへの注意が照合作業に取られ、見落としが減らない（#523）                                                                                                |
| 判定基準の出どころ（ポリシー・その節）で割る           | 読むポリシーやその節ごとにレンズを作る（#269 の `/requirements-review` の当初の形） | ポリシーに基準の無い観点（`/code-review` のロジックの正しさ）の担当が立たない。ポリシーごとに割ると「コメントだけ」のような狭すぎるレンズができる（#486・#523） |
| 取りこぼしを確かめず、「1起動1問い」の原則だけで分ける | 1体で足りるかを確かめずに、どのレビューも分ける                                     | 効果を測らずに費用だけが増える。1体の plan-reviewer-agent は仕込んだ抜けを3回とも拾った（#531・#541）                                                           |

## トレードオフ・影響

| 受け入れる制約・リスク                             | 影響範囲                   | 緩和策                                                                                                   |
| -------------------------------------------------- | -------------------------- | -------------------------------------------------------------------------------------------------------- |
| 起動の回数と費用がレンズの数だけ増える             | 分けたレビューの毎回の実行 | 分けるのは1体の取りこぼしが確かめられたときだけにする                                                    |
| 束ね方に漏れがあると、どのレンズも見ない観点が出る | 分けたレビューの判定       | 観点一覧の全行がどれかのレンズに入っているかを突き合わせる（穴出し）。各レンズに判定した観点を申告させる |
| 並列のレンズは互いを見られず、逆向きの指摘が出うる | 統合するメインセッション   | 統合での判断を食い違いの裁定だけに限る                                                                   |
