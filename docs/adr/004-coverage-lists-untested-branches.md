# ADR-004: テストの無い分岐はカバレッジで挙げ、LLM はテストを書くべきかだけを判定する

## 決定（何を選んだか）

`/code-review` のテストレンズは、ワークスペースの `npm run test:coverage` を実行し、出てきた `coverage/coverage-final.json` から未実行の分岐（正常系・異常系）を機械的に挙げる。LLM は、挙がった分岐にテストを書くべきかだけを判定する。計測できないときは LLM が分岐を挙げ、報告に「カバレッジ未計測（理由）」と書く。

## 採用理由（なぜこれを選んだか）

分岐を漏れなく挙げる作業は機械で解けるので、LLM に任せない（`docs/policy/refined-engineer-judgment-principles.md`「確率論より決定論」）。`docs/policy/unit-test-policy.md`「グレーボックステストで書く」も、テストの過不足はカバレッジで確かめると定めている。

## 検討した代替案（なぜ却下したか）

**決定の軸：テストの漏れ（テストの無い分岐）をどう挙げるか。**

| 案                                       | 内容                                                              | 却下理由                                                                                             |
| ---------------------------------------- | ----------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| LLM に分岐を挙げさせる（元のやり方）     | LLM が実装の分岐を読んで挙げ、テストファイルと1つずつ突き合わせる | 分岐が多いほど挙げ漏れが残る。元の観点は異常系しか見ておらず、正常系の漏れが素通りしていた           |
| カバレッジを目標値付きの CI ゲートにする | CI でカバレッジを測り、目標値に届かなければ落とす                 | `docs/policy/unit-test-policy.md`「カバレッジの考え方」が目標値の強制を禁じている（Goodhart の法則） |
