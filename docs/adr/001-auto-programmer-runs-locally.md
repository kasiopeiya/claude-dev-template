# ADR-001: Issue を自動実装するオーケストレーターをローカルで走らせる

> [!IMPORTANT]
> **TL;DR（この決定の要点）**
>
> - ボードの Ready を拾って PR まで運ぶ `auto-programmer` は、開発者のマシン上でローカル実行する
> - 作業は AI 専用 clone の中だけで行い、人間の作業ツリーには触れない
> - 対価として、起動は人間が `npm run auto-programmer` を打つことに依存する（自動起動はしない）

## コンテキスト（なぜ決めるのか）

Issue を AI に実装させる経路は、前段（`/quick-issue`・`/issue-check`・`/issue-deps`）も後段（`pipeline.yml` → `pr-ai-triage.yml`）も揃っているのに、「Ready のカードを拾って PR を作る」一区間だけが無い。この区間を埋めるにあたり、**その処理をどこで走らせるか**を先に決める必要がある。

既存の `/sweep` は「ブランチは切らない。現在のブランチでそのまま作業する」と定め、作業ツリーが汚れているかを着手前に検査しない。つまり「いま作業してよいブランチ・汚れていないツリー」という前提を、人間が起動タイミングを選ぶことで外から供給している。人間の手を離して走らせるなら、この前提を別の形で用意しなければならない。

## 決定（何を選んだか）

`auto-programmer` は開発者のマシン上でローカル実行する。作業対象は、リポジトリを別の場所へ clone した **AI 専用 clone** に限る。

| 作業ツリー       | 誰が使うか             | AI が触るか                        |
| ---------------- | ---------------------- | ---------------------------------- |
| 人間の作業ツリー | 人間（編集・コミット） | 触らない                           |
| AI 専用 clone    | `auto-programmer`      | ブランチ作成・実装・コミット・push |

## 採用理由（なぜこれを選んだか）

ローカルなら、hook・Policy・SubAgent を含むこのリポジトリのハーネスがそのまま動き、実行時間の上限もない。Projects の読み書きも、ローカルの `gh auth` をそのまま使えるため追加の認証情報を要しない。

作業ツリーを AI 専用 clone へ分けることが、`/sweep` が人間の起動タイミングから受け取っていた前提（作業してよいブランチ・汚れていないツリー）の代替物になる。clone を1つ常設して使い回すので、`node_modules` も使い回せる。

## 検討した代替案（なぜ却下したか）

**決定の軸：Issue 1件を実装する処理をどこで走らせるか。**

| 案                        | 内容                                                           | 却下理由                                                                                  |
| ------------------------- | -------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| GitHub Actions の定期実行 | スケジュール起動の job で Ready を拾い、実装して PR を作る     | job の実行時間に上限があり、Projects の Status を読むのに project スコープ付き PAT が要る |
| セッション内の `/loop`    | 人間が開いているセッションで、`/loop` に同じ処理を繰り返させる | 同じセッションに文脈が積もるほど品質が落ち、ターミナルを閉じると止まる                    |

## トレードオフ・影響

| 受け入れる制約・リスク                                | 影響範囲                 | 緩和策                                                                                                                                       |
| ----------------------------------------------------- | ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------- |
| 起動は人間が打つコマンドに依存する                    | Issue の消化速度         | なし（自動起動は、自分で起動するのが面倒になってから足す）                                                                                   |
| clone が1つ増え、初回だけ依存のインストール待ちが出る | 開発者のマシンのディスク | clone と依存のインストールを起動時に自動で済ませる                                                                                           |
| AI の作業が人間の作業ツリーに現れない                 | 結果の確認手段           | 結果は PR として GitHub に出る。ローカルを覗かなくても差分を読める                                                                           |
| 権限確認を飛ばして `claude` を起動する                | AI 専用 clone の中       | 影響範囲が clone 内に閉じる。`.claude/hooks/` のガードは clone 内でも効き続ける。起動は人間に限り、AI のセッションからの起動は hook が止める |
