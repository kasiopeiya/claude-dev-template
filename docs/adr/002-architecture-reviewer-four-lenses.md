# ADR-002: architecture-reviewer-agent を4レンズに分ける

## 決定（何を選んだか）

architecture-reviewer-agent が見る観点を、対象に向ける問いの種類で4レンズに束ねる。

- **差し替えて壊す**：詳細を差し替えたら、どこまで壊れるか
- **結合を測る**：離れた2箇所が、暗黙の知識を共有していないか
- **投資の較正**：境界と決定への投資を、いま揺れうる重要な詳細に絞れているか（作りすぎ・決めすぎ）
- **意図が読めるか**：構造を見ただけで、何のためのシステムか分かるか

## 採用理由（なぜこれを選んだか）

`docs/policy/review-subagent-lens-policy.md`「束ね方は『対象に向ける問い』ごとにする」に従った。ポリシーの節ではなく読み方の違いで束ねることで、変更プローブで実測する・2箇所の証拠を突き合わせる・要件やADRと照らして投資の過不足を見る・ディレクトリ構成を読む、という4つの異なる読み方をレンズごとに独立させた。

## 検討した代替案（なぜ却下したか）

**決定の軸：architecture-reviewer-agent の観点をレンズにどう束ねるか。**

| 案                                | 内容                                                                                      | 却下理由                                           |
| --------------------------------- | ----------------------------------------------------------------------------------------- | -------------------------------------------------- |
| 3レンズ                           | Connascence（結合を測る）と Screaming Architecture（意図が読めるか）を1レンズに同居させる | 読み方の違う問いが混ざる                           |
| Issue #533 当初の4レンズ          | 「新規開発の進め方」を丸ごと「意図が読めるか」に置き、較正を2レンズに残す                 | 読み方の違う問いが混ざり、較正で逆向きの指摘が出る |
| 2レンズ（変更プローブ／それ以外） | 変更プローブが走るレンズと、それ以外の観点をまとめたレンズの2つに分ける                   | 「それ以外」に複数の異なる問いが混ざる             |
