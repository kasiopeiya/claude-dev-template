# ADR-008: 週次 docs 整合性チェックの起点を、前回処理を終えた週次 Issue 以降に変わった `docs/**/*.md` にする

## 決定（何を選んだか）

`scripts/doc-consistency-weekly-issue.mjs` は、`/doc-consistency` に渡す起点（対象ファイル）を、実行結果コメントが付いた直近の週次 Issue の HEAD SHA から今回の HEAD までに変わった `docs/**/*.md` に絞る。該当する週次 Issue が無い、または SHA を読み取れない場合だけ、これまでどおり `docs/` 全体を対象にする。

## 採用理由（なぜこれを選んだか）

2文書の間の重複・矛盾は、どちらかが変わったときにしか生まれない。最初に1回全体を見て、以後の変更を途切れずに起点へつなげれば、すべての組み合わせを一度は見たことになる。処理が1週遅れても、次の実行時にその分の期間をまとめて起点に含められるため、抜けが出ない。

## 検討した代替案（なぜ却下したか）

**決定の軸：週次チェックの起点を、毎回どう決めるか。**

| 案        | 内容                                                            | 却下理由                                                                                                                                     |
| --------- | --------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| 直近2週間 | 起点を「今から2週間前」に固定し、そこから HEAD までを対象にする | 週次 Issue が2週間より長く放置されると変更が漏れ、毎週処理されれば1週分を二度見る                                                            |
| 毎回全体  | 起点を持たず、常に docs/ 全体を対象にする                       | 文書が増えるほど1回の時間とコストが伸びる。AI の見落としを拾い直す利点は、引数なしの `/doc-consistency` を手動実行すれば必要なときに得られる |
