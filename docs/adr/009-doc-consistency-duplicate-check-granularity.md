# ADR-009: `/doc-consistency` の重複確認はまとめ Issue の指摘単位で行い、完了済みと同じ指摘は再発として起票する

## 決定（何を選んだか）

`/doc-consistency` が起票する `[重複]` のまとめ Issue は、`gh issue list --state all --search "<事柄>"` を**指摘ごとに**実行し、open または `NOT_PLANNED`（却下済み）の既存 Issue に同じ指摘が載っていたら、その指摘はまとめから外す。`[矛盾]`・`[重複]` とも、`state reason: COMPLETED` で閉じた Issue と同じ指摘（同じ2文書・同じ事柄で判定する）が再び見つかったら、重複扱いで捨てずに再発として新規起票する。既存の `/quick-issue` の重複確認（Issue 単位・`--state all` で検索する仕組み）はそのまま使い、新しい確認の仕組み（スクリプト・DB など）は作らない。

## 採用理由（なぜこれを選んだか）

`/quick-issue` の重複確認は Issue 単位の検索なので、`[重複]` のように複数の指摘を1件のまとめ Issue に束ねる場合、中の指摘1件ずつの重なりまでは見えない。既存の確認の粒度を Issue → 指摘に合わせるだけで、新しい仕組みを増やさずに漏れを防げる。

## 検討した代替案（なぜ却下したか）

**決定の軸：`/doc-consistency` の起票で「同じ指摘」の再起票をどう防ぐか。**

| 案                                           | 内容                                                                 | 却下理由                                                       |
| -------------------------------------------- | -------------------------------------------------------------------- | -------------------------------------------------------------- |
| open の Issue だけを見て同じ指摘を起票しない | 検索を `--state all` ではなく open 限定にする                        | 既存の確認より狭く、却下済み（NOT_PLANNED）の指摘を起票し直す  |
| 重複を許す                                   | まとめ Issue が既存 Issue と重なっても気にせず起票する               | 週次チェック（#496）のたびに片付いていない指摘が積み増しになる |
| 週次 Issue の起票を止める                    | 前回の指摘 Issue が open の間、次の週次まとめ Issue の起票を保留する | 人間の判断待ちの指摘が残ると定期チェックが止まり続ける         |
