# ADR-007: `/doc-consistency` は通常開発の実装フローに含めない(文書の分割・統合作業は例外)

## 決定(何を選んだか)

通常開発の Issue の実装フロー（CLAUDE.md「変更種別ごとの使用Skill」）には `/doc-consistency` を含めない。`/doc-consistency` は、週次の定期チェックと人間の明示的な指示でだけ起動する。ただし、文書の分割・統合・規定の移動そのものが作業内容である Issue では、実装フローに含めてよい例外とする。

## 採用理由(なぜこれを選んだか)

通常開発の Issue のたびに docs/ 全体を横断する重いチェックを走らせると、週次チェックと同じファイルを毎回二重に見ることになる。一方、文書の分割・統合・規定の移動を行う Issue では、重複・矛盾が生まれていないことの確認そのものが作業の完了確認になるため、この作業に限り実装フローに含める。

## 検討した代替案(なぜ却下したか)

**決定の軸：通常開発の実装フローで `/doc-consistency` をどう扱うか。**

| 案                                                   | 内容                                                                | 却下理由                                                                                |
| ---------------------------------------------------- | ------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| 例外を設けず、常に通常開発の実装フローから外す       | 文書の分割・統合作業でも `/doc-consistency` を実装フローに含めない  | 分割・統合作業で重複・矛盾が生まれていないことを確かめる手段が無くなる                  |
| 通常開発の実装フローに含め、週次とは別に継続して回す | すべての通常開発 Issue の実装フローに `/doc-consistency` を組み込む | 差分レビューで足りる場面まで毎回 docs/ 全体を横断チェックすることになり、開発が重くなる |
