# ADR-014: 「どれを選ぶか」は Policy に、選んだ後の How は Rule に分けて置く

## 決定（何を選んだか）

判断の基準を、答える問いで2か所に分けて置く。

| 置き場所                 | 答える問い                                         | 例                           | 届き方                                                              |
| ------------------------ | -------------------------------------------------- | ---------------------------- | ------------------------------------------------------------------- |
| Policy（`docs/policy/`） | 正解が複数ある中で、どれを選ぶか（流派・優先順位） | モックを避ける古典学派で書く | `hook.applies-to` に合うファイルの編集前に policy-loader が指し示す |
| Rule（`.claude/rules/`） | 選んだ後に、どう書くか・どう作るか                 | AAA の Act は必ず1行         | `paths` に合うファイルを Read した時点で読み込まれる                |

## 採用理由（なぜこれを選んだか）

Policy と Rule は目的が違う。Policy は判断を AI に委ねて出力のぶれを抑えるためのもので、Rule は書き方をそろえてレビューで直す手間をなくすためのものである。

1か所に同居させると、判断軸を読ませたい Policy の中に書式・命名などの How が埋もれる。Policy も膨らみ（unit-test-policy は523行、requirements-doc-policy は593行あった）、編集のたびに丸ごと読ませることになる。分けておけば、How は Rule の文字数上限で読み込み量を抑えつつ、対象ファイルを読んだ時点で届く。

## 検討した代替案（なぜ却下したか）

**決定の軸：立場と How を、どの線で Policy と Rule に振り分けるか。**

| 案                           | 内容                                                  | 却下理由                                                            |
| ---------------------------- | ----------------------------------------------------- | ------------------------------------------------------------------- |
| Policy に両方を置く          | 立場も How も Policy に書き、Rule は使わない          | How が判断軸の中に埋もれ、Policy が膨らみ続ける（#500・#558・#565） |
| 「コードの書き方か」で分ける | コードの書き方だけを Rule に置く（#498 より前の定義） | 文書やテストの How が Policy に残る（#498）                         |

## トレードオフ・影響

| 受け入れる制約・リスク                                            | 影響範囲                                      | 緩和策                                                                                  |
| ----------------------------------------------------------------- | --------------------------------------------- | --------------------------------------------------------------------------------------- |
| 新規ファイルは Read されないので、Rule が標準ロードで届かない     | 新しくファイルを作る作業                      | 対象ファイルがまだ無いときだけ、policy-loader が `paths` の合う Rule も指し示す（#544） |
| Rule の文字数上限（6,000文字）に How が収まらないことがある       | `paths` を狭められない Rule（要件定義書など） | Rule をリンクだけのスタブにし、本体を `.claude/rule-bodies/` に置く（#570）             |
| 立場と How が文中で絡む Policy は、見出し単位では切り分けられない | 移し替えの作業                                | 1文ずつ仕分けて移す（#565）                                                             |
