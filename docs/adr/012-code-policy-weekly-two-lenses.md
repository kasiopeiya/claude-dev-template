# ADR-012: 週次コード Policy 準拠チェックは「決まりどおりか」「設計の形」の2レンズだけを実行する

## 決定(何を選んだか)

週次コード Policy 準拠チェックの Issue が依頼する `/code-review` の実行は、`--lens 決まりどおりか` と `--lens 設計の形` の2回に固定する。バグ探し・セキュリティ・テストの3レンズは対象外にする。

## 採用理由(なぜこれを選んだか)

このチェックの目的は「Policy・Rule を変えたときに違反になった、差分の無い既存コード」を拾うことである。重複コード（SSoT違反）・単一責任・アプリ設計ポリシー準拠は「設計の形」レンズの担当で、「決まりどおりか」レンズには含まれない。この2レンズで、既存コードが陳腐化した Policy・Rule と手本の役割を両方拾える。バグ探し・テストは既存コードの潜在バグ・テストの穴を狙うレンズで、Policy 変更とは無関係に毎週同じ指摘を繰り返しやすい。

## 検討した代替案(なぜ却下したか)

**決定の軸：週次コード Policy 準拠チェックで、どのレンズを実行するか。**

| 案                    | 内容                                               | 却下理由                                                                                         |
| --------------------- | -------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 「決まりどおりか」1本 | レンズを1本に絞り、実行コストを半分にする          | 重複コード・単一責任・アプリ設計ポリシー準拠は「設計の形」レンズの担当であり、観点の半分が落ちる |
| 全5レンズ             | バグ探し・セキュリティ・テストも含めて毎週実行する | コストが2.5倍になり、バグ探し・テストは Policy 変更と無関係に前週と同じ指摘を繰り返しやすい      |
