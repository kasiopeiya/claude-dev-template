# 起票先（このプロジェクトが使うルート Issue）

分解元の親が無い Issue を、どのルート Issue（Issue 階層の最上位の常設 Issue）の下に入れるかを決める。読むのは `/link-root-issue` で、方針は [issue-policy](../policy/issue-policy.md) が持つ。

> [!NOTE]
> このファイルはテンプレート同期の対象外なので、書き換えてもテンプレート側の更新で戻らない。下の表はテンプレート本体のもの。**このテンプレートを使うプロジェクトは、自分の起票先に書き換える。** 新規開発ガイドで起点 Issue（ガイドが要件定義書から作る、親が種別で決まる Issue）を作るなら、表の代わりに「issue-policy の標準のルートを使う」と書く（ガイドが標準のルートの名前、たとえば要件定義をルート名として渡し、ファイルに無い名前だと `/link-root-issue` が紐づけずに終えるため）。

## 振り分け条件

上の行から当て、最初に当たった行で決める。既定の行は最後に置く。条件は、ラベルや触るパスのように、外から見て分かる事実で書く。

| 条件                           | ルート | ルートの本文（作るときに書く）                                                  |
| ------------------------------ | ------ | ------------------------------------------------------------------------------- |
| `broken-window` ラベル付き     | 改善   | AI が作業中に見つけた問題の Issue をぶら下げる常設 Issue                        |
| 既定（上のどれにも当たらない） | 構築   | 人間が依頼した、このテンプレート自体を作る・育てる Issue をぶら下げる常設 Issue |
