# テスト戦略設計

このシステムのテストを書く・レビューする開発者／AI が、**どのテストで何を保障するのか**を知りたいときに参照する。  
個々のテストコードは実装が正であり、本書はそこから読み取れない層の切り分けと、その理由を書く。

> **用語の定義（unit／integration／E2E・テストダブル）は [test-terms.md](../reference/test-terms.md) が SSOT** なので、ここには書き写さずリンクする。

> **本書が書くのは、このプロジェクトで各層が**実際にどこからどこまでを対象にし、何を保障するか**という境界そのもの。

## 基本方針

### 単体テストは古典学派スタイル

単体テストポリシーに従い、以下の設計方針をとる。

| 方針                   | 理由                                                                                                                                                    |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 古典学派スタイルを採用 | リファクタリングに強く、メンテナンスが容易だから                                                                                                        |
| グレーボックステスト   | カバレッジ100%を目標とするのは明確なアンチパターンであり、カバレッジを目標にしない しかしテストの過不足を確認するためのツールとしてカバレッジは使用する |

### 価値あるテストだけを書く

テストは重要な人間レビュー対象であり、レビューを容易にするためにも対象を厳選する。  
テストコードは負債であるという思想。
