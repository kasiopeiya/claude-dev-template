# レビューレポートフォーマット

`/doc-review` が Phase 3 で、各レンズの結果を統合して出すときの書式。観点の判定基準は review-criteria.md に置く。

点数・良い点・総評は、どの欄にも書かない。結果を使う側（/design など）は指摘の有無と severity だけで直すかを決めており、良い点を求めると、見る観点の少ないレビューでは良い点のでっち上げを招く。

## レポート全体

```
## Doc Review Report

<!-- Issue 情報を受け取ったときだけ、次の1行を置く -->
**レビューコンテキスト**: Issue #<番号>「<タイトル>」に基づく更新のレビュー

### 🔍 レンズごとの判定した観点

<!-- レンズごとに1行。各レンズの生レポートにある「判定した観点」をそのまま転記する。転記漏れがあると、次の「未判定の観点」が信頼できなくなる。起動条件に当てはまらず起動しなかったレンズは「起動せず（対象の文書なし）」と書く -->

| レンズ | 判定した観点 |
| --- | --- |
| <レンズ名> | <列挙> |

### ❓ 未判定の観点

<!-- review-criteria.md の観点一覧の全行のうち、上の表のどこにも名前が挙がっていないものを列挙する。起動しなかったレンズの担当観点は入れない（各文書の表で「対象外」と書く）。無ければ「なし」 -->

- <観点名>（無ければ「なし」）

---

<!-- 対象文書ごとに、ここから「繰り返しここまで」までを繰り返す -->

## 文書: `<ファイルパス>`

### 📁 文書情報
- **種別**: <doc-types.md の種別>
- **人間向け文書**: <はい / いいえ>
- **最終更新**: <git log による最終コミット情報>

### 📋 観点ごとの判定

<!--
review-criteria.md の観点一覧を上から順に全行書き出す（行を省かない）。観点名は一覧の行名と一字一句同じにする。
判定は 準拠 / 違反 / 対象外 / 未判定 のいずれか。違反の行には、下の「改善が必要な点」に出した指摘の数を書く。
-->

| 観点 | 判定 | 指摘の数 |
| --- | --- | --- |
| <観点一覧の行名> | <準拠 / 違反 / 対象外 / 未判定> | <違反なら件数、それ以外は -> |

---

### 🔧 改善が必要な点

#### 🚨 [必須]
<!-- 無ければ「なし」 -->

- **<観点名>**: <具体的な問題の説明>
  - **場所**: <節名>（`<ファイルパス>:<行番号>`）
  - **引用**: <対象文書からコピーした原文1〜3行。欠落の指摘なら、欠落を確認した範囲の原文>
  - **改善案**: <具体的な改善方法。レンズ間で食い違った場合は裁定で採った案を書き、捨てた案と根拠の条文を添える>
  - **理由**: <なぜ問題か>

#### ⚠️ [推奨]
<!-- 無ければ「なし」 -->

（書式は [必須] と同じ）

#### 💡 [提案]
<!-- 無ければ「なし」 -->

（書式は [必須] と同じ）

---

### 🚀 次のステップ（優先度付き）

<!-- 指摘が無ければ「なし」と書く -->

1. **[高] <[必須] の指摘の観点名>**: <改善案を1行で>
2. **[中] <[推奨] の指摘の観点名>**: <改善案を1行で>
3. **[低] <[提案] の指摘の観点名>**: <改善案を1行で>

<!-- 繰り返しここまで -->
```

複数の文書をレビューしたときは、この後に「全体サマリー」を出す。最後に1回だけ `**レビュー完了**` と書く。

## 全体サマリー（複数の文書をレビューしたとき）

各文書のレポートをすべて出した後に1回だけ出す。

```
## Doc Review Summary

| 文書 | 種別 | [必須] | [推奨] | [提案] |

| `<ファイルパス>` | <種別> | <件数> | <件数> | <件数> |
```
