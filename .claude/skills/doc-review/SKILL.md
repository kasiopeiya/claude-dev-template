Markdown 文書をレビューしてください。あなたはレビュー本体を行わず、**レンズに割って並列に走らせ、返ってきた結果を統合する**役です。

1体に全観点を見せると、矛盾探し・読み手の目・削る目・規約と見比べる・異常ケース探しという性質の違う問いが1回の起動に同居し、どれかへの注意が薄まります。レンズごとに並列に走らせ、判定・severity・改善案はレンズ側に決め切らせ、あなたには手順どおりの決定・統合だけを残します。

## Phase 1: 対象文書・判定範囲・種別・最終コミット情報を決める

まず引数を、**`--full` の有無**、**`--lens <レンズ名>`**、**ファイルパス**、**それ以外の指示**（呼び出し側が渡す Issue 情報・要件定義書との照合の指示）に分ける。

### `--lens` を読み、起動する候補のレンズを決める

`.claude/agents/doc-reviewer-agent/doc-reviewer-agent.md` の「レンズ一覧と担当観点（正典）」を Read する。

- `--lens` が無い場合：候補のレンズはレンズ一覧の全レンズ
- `--lens <レンズ名>` がある場合：レンズ名がレンズ一覧に無ければ「指定されたレンズ名が一覧にありません: <レンズ名>」と出力して終了する。あれば、候補のレンズはそのレンズ1つだけ

決めた「候補のレンズ」を、この後の Phase 2・Phase 3 に渡す。「起動する条件」との照合は、対象文書が決まった後の Phase 2 で行う。

### ファイルパスが無い場合

Bash で以下の 2 コマンドを実行する（1つ目は未コミットの変更、2つ目は未追跡の新規ファイル）:

```bash
git diff HEAD --name-only --diff-filter=ACMR
git ls-files --others --exclude-standard
```

2 つの結果を結合し、重複を除去してから、`.md` で終わるファイルだけを残す。

該当ファイルが 0 件の場合は「git diff/status に対象 Markdownファイルが見つかりませんでした」と出力して終了する。

### ファイルパスがある場合

そのファイルパスを直接対象とする（複数指定可）。

### 要件定義書を外す

対象に `docs/requirements.md` があれば一覧から外し、「requirements.md は /requirements-review で専用レビューしてください」と出力する。外した結果 0 件なら終了する。

### 判定範囲を決める

対象文書ごとに、判定範囲を **差分** か **全文** に決める。

| 条件                                                               | 判定範囲 |
| ------------------------------------------------------------------ | -------- |
| 引数に `--full` がある                                             | 全文     |
| `git diff HEAD -- <パス>` に出力がある、または未追跡の新規ファイル | 差分     |
| どちらでもない（パスを指定したが変更が無い）                       | 全文     |

差分の文書は、Phase 3 の共通手順の手順1で引用と突き合わせるため、ここで `git diff HEAD -U0 -- <パス>` を1回だけ取っておく（未追跡の新規ファイルは全行が追加行）。

### 種別と文書情報を決める

> [!IMPORTANT]
> **（AI・必須）** 種別と人間向け文書かどうかは、`references/doc-types.md` を Read してから、そのルールだけで決めてください。会話に判定表の引用・過去のレビュー結果・種別の言及があっても、それらを判定の根拠にしてはいけません。

対象文書それぞれについて、`references/doc-types.md` で種別と人間向け文書かどうかを決め、続けて最終コミット情報を取得する:

```bash
git log -1 --pretty=format:"%h - %an, %ar : %s" -- [ファイルパス]
```

対象文書・判定範囲・種別・人間向け文書かどうか・最終コミット情報の組を、この後の全レンズ起動に渡す（レンズごとに決め直させない）。差分の中身はプロンプトに書き写さない——各レンズが `git diff HEAD -- <パス>` で自分で取る。書き写すと、その分がレンズの数だけ出力トークンになる。

## Phase 2: レンズを並列起動する

`doc-reviewer-agent` を、**起動するレンズごとに1回ずつ、1メッセージ内でまとめて** Task 起動する。逐次に投げると、待ち時間がレンズの数だけ積み重なる。

起動するのは、Phase 1 で決めた候補のレンズのうち、「起動する条件」が Phase 1 で決めた対象文書に当てはまるものだけ。当てはまらないレンズは起動せず、名前を Phase 3 に持ち越す（探す対象の無い文書に当てると、裏の取れない指摘が出る）。`--lens` で指定したレンズが当てはまらないときは、起動せず「指定されたレンズは対象文書に当てはまりません: <レンズ名>」と出力して終了する。

各起動には次を渡す:

- **レンズ名**：レンズ一覧のうち1つ
- **対象文書の一覧**：Phase 1 で決めた全文書。各文書にパス・判定範囲（差分／全文）・種別・人間向け文書かどうか・最終コミット情報を添える
- **Issue 情報**：引数に含まれていれば、全レンズに渡す
- **要件定義書との照合の指示**：引数に含まれていれば、**「規約と見比べる」レンズにだけ**渡す

**レンズの一覧と担当観点は `doc-reviewer-agent` の定義が正典です。** ここに書き写しません——2箇所に持つと、割り方を変えたときに片方が古いまま残ります。

## Phase 3: 統合してレポートを出す

[`.claude/rule-bodies/review-integration.md`](../../rule-bodies/review-integration.md) を Read し、その手順に従う。この Skill が足す内容は次のとおり:

- **手順6に足す**：`--lens` があれば、観点一覧の全行ではなく、起動した1レンズの担当観点だけを対象にし、突き合わせる相手も起動した1レンズにする。起動条件に当てはまらず起動しなかったレンズの担当観点は、未判定に入れず、全文書で「対象外」と書く（未判定に入れると、割り方の穴と取り違える）
- **手順7に足す**：Critical の合計は、対象の全文書を通じて数える（`--lens` があれば、起動した1レンズの指摘だけの合計）

指摘は文書ごとにまとめる。複数の文書を渡した場合も、レンズをまたいで同じ文書の指摘を1箇所に集める。

出力は `references/report-format.md` の書式に従う。
