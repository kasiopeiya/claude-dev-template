# アーキテクチャレビューレポートフォーマット

`/arch-review` が Phase 3 で、各レンズの結果を統合して出すときの書式。観点の判定基準は `review-criteria.md` に置く。

点数・総合評価・良い点は、どの欄にも書かない（`review-subagent-lens-policy.md`「レンズに分けるレビューは採点しない」）。結果を使う側は指摘の有無と severity だけで直すかを決める。

## レポート全体

```
## アーキテクチャレビュー結果

**レビュー対象**: <設計書のみ / コードのみ / 両方> — <対象の具体>
**新規開発かどうか**: <新規開発 / 既存改修>（新規開発のみ対象の観点の対象可否を左右する）
**判定した範囲**: <差分 / 全文>（差分なら、前からある違反は判定していない。全文の判定は `--full`）

### 🔍 レンズごとの判定した観点

<!-- レンズごとに1行。各レンズの生レポートにある「判定した観点」をそのまま転記する。転記漏れがあると、次の「未判定の観点」が信頼できなくなる -->

| レンズ | 判定した観点 |
| --- | --- |
| <レンズ名> | <列挙> |

### ❓ 未判定の観点

<!-- review-criteria.md の観点一覧の全行のうち、上の表のどこにも名前が挙がっていないものを列挙する。無ければ「なし」。これはレビュー対象の欠陥ではなく、レンズの割り方の穴 -->

- <観点名>（無ければ「なし」）

### 🚦 合否

<!--
合否の判定基準は ai-review-gate-policy（../../../../docs/policy/ai-review-gate-policy.md）「合格条件は『残してよい例外以外のCriticalが0件』」。
ここで数える Critical は、全観点を通じた合計から、このレビュー内で「食い違いの裁定」により issue:needs-human-decision として起票した食い違いに含まれる Critical の指摘数を引いたもの（起票した食い違いの件数ではない）。
-->

- **判定**: <🚫 要修正 / ✅ 合格>
- **Critical残数**: <上の計算による件数>
- **Issue にして残す Critical**: <issue:needs-human-decision として起票した Issue 番号と概要。無ければ「なし」>

| ----------------- | ------ | -------------------- | ---- |
| <例: Value（強）> | 遠い   | <pathA> ↔ <pathB>    | ✕    |

<計上ゼロなら「ファイルをまたぐ有害な結合なし」と1行で書く>

### 📋 観点ごとの判定

### 🔧 改善が必要な点

#### 🚨 Critical
<!-- 差し替え時に広く壊れる急所など。severity の決め方は review-criteria.md 参照 -->

- **<観点名>**: <具体的な問題の説明>
  - **引用**: <レンズの引用条件（観点により1箇所 or 2箇所。architecture-reviewer-agent「レビューの前提」参照）を満たす引用。判定範囲が差分なら、少なくとも1箇所は原因になった差分の行>
  - **理由**: <何を替える・足すと何が壊れるか／何が無駄になるか>
  - **改善案**: <境界を引く・削る、決定を遅らせる、など構造の変え方。レンズ間で食い違った場合は裁定で採った案を書き、捨てた案と根拠の条文を添える>

#### 💡 Medium

  - **改善案**: <改善の方向>

<引用条件を満たせない指摘は書かない。ある severity に指摘が無ければ、その小見出しの下に「なし」と1行で書く>
```
