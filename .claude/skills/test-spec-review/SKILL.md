テストを要件定義書の規則に照らしてレビューしてください。あなたはレビュー本体を行わず、**`test-spec-reviewer-agent` を走らせ、返ってきた結果を統合する**役です。

## 範囲

範囲は、引数で次の3つから決める。**範囲が決めるのは、照らす規則だけである。** agent に渡すテストファイルの一覧は、どの範囲でも同じにする。

| 引数             | 範囲           | 照らす規則                           |
| ---------------- | -------------- | ------------------------------------ |
| 無し             | 今の差分       | 差分のテスト・実装が触れる規則       |
| `--all`          | 全部           | 要件定義書の規則すべて               |
| それ以外の文字列 | 名指しした機能 | その機能の記述と、その機能が使う規則 |

- 引数が `--all` と完全に一致したときだけ「全部」にする。それ以外の文字列は、1つの機能名としてそのまま使う（要件定義書の ID の形に限らない。分割もしない）
- どの範囲でも、その規則のテストの欠け・食い違いは、差分の前からあるものも出す

`test-spec-reviewer-agent` は Bash を持たないので、テストファイルの一覧（範囲が今の差分のときは差分も）は、あなたが取ってファイルに書き、そのパスを渡します。

## なぜ `/code-review` のレンズにしないか

`/code-review` は、差分か渡したパスの `.ts`・`.tsx` ファイルを対象に始まる。このレビューの単位は要件定義書の規則で、規則のテストは差分の外の既存のテストファイルにもある。機能名と全部の範囲では、差分がそもそも無い。対象の集合が違うので、review-subagent-lens-policy「対象の集合が違う観点は、取りこぼしを待たずに分けてよい」に従い、別の Skill と agent にした。`/code-review` のレンズに足すと、差分の外の追跡済みテストファイルまで集めて渡す手順を、ほかのレンズは使わない。既存のテストレンズに足すと、対象の集合が違う観点を既存レンズに混ぜることになる。`code-reviewer-agent` を流用すると、TypeScript コード用の agent に要件定義書を読む役が混ざる。

## Phase 1: 要件定義書と対象を決める（1回だけ）

### 要件定義書を確かめる

`docs/requirements.md` と `docs/requirements-detail.md` がどちらも無ければ、「照らす要件なし（docs/requirements.md・docs/requirements-detail.md がありません）」と出力して終了する。中身が見出しだけかどうかは、ここでは判定しない（agent が照らす規則を探し、無ければ「照らした要件」を「なし」と返す）。

### 差分の対象を集める（範囲が今の差分のときだけ）

機能名と全部の範囲では、この節を飛ばし、次の節へ進む。

Bash で `git diff HEAD --name-only --diff-filter=ACMR`（未コミットの変更）と `git ls-files --others --exclude-standard`（未追跡の新規ファイル）を実行して結合し、重複を除いた中から `.ts`・`.tsx` で終わるファイルを集める。要件定義書などの `.md` は含めない（規則を書いた側の変更は、テストが触れた規則ではない）。

0件なら「差分に .ts・.tsx のファイルがありません」と出力して終了する。

### 差分ファイルとテストファイルの一覧を書く

テストファイルの一覧（範囲が今の差分のときは、追跡済みの対象の差分も）を、`tmp/`（git 管理外）配下に書く。コマンドは1本ずつ分けて打つ。worktree に入ったセッションでは、git を含む複合コマンドが止められるためである。まず書き先を作る。

```bash
dir=tmp/test-spec-review/$(date +%Y%m%d-%H%M%S) && mkdir -p "$dir" && echo "$dir"
```

出力されたパスを、以下の `<dir>` にそのまま書く（シェル変数は Bash ツールの呼び出しをまたいで残らない）。範囲が今の差分のときは、追跡済みの対象ごとに1本、差分を書く。

```bash
git diff HEAD -- <パス> > <dir>/<パスの / を __ にした名前>.diff
```

テストファイルの一覧を、どの範囲でも2本で書く。

```bash
git ls-files '*.test.ts' '*.test.tsx' '*.spec.ts' '*.spec.tsx' > <dir>/test-files.txt
git ls-files --others --exclude-standard '*.test.ts' '*.test.tsx' '*.spec.ts' '*.spec.tsx' >> <dir>/test-files.txt
```

テストファイルの一覧は、差分のテストだけでなく、追跡されたテストファイル全体にする。差分や機能に関わるテストが既存のどのファイルにあるかは、Skill が先に決められず、絞ると取りこぼす。差分のファイルだけを渡すと、規則のテストが既存のファイルにあっても見えず、「テストが無い」と過検知する。`.test.mjs` は含めない（このリポジトリではハーネスのスクリプトのテストで、プロダクトの要件を確かめるものではない）。

未追跡の新規ファイルは差分ファイルを書かない（全行が追加行なので、agent は対象ファイルを読めば足りる）。

## Phase 2: レンズを起動する

`.claude/agents/test-spec-reviewer-agent/test-spec-reviewer-agent.md` の「レンズ一覧と担当観点（正典）」を Read し、レンズごとに1回ずつ、**1メッセージ内でまとめて** `test-spec-reviewer-agent` を Task 起動する。

各起動には次を渡す。差分の中身はプロンプトに書き写さない。

- **レンズ名**：正典の表記のまま
- **範囲**：`今の差分`、`全部`、または `機能名：<引数の文字列をそのまま>`
- **要件定義書のパス**：`docs/requirements.md` と `docs/requirements-detail.md` のうち、あるもの
- **差分の対象ファイルの一覧**（範囲が今の差分のときだけ）：各ファイルのパスと、差分ファイルのパス（書いたものだけ）
- **テストファイルの一覧のパス**：Phase 1 のコマンドが最後に出力したディレクトリ（`tmp/test-spec-review/<日時>`）の `test-files.txt`。`$dir` のまま渡さず、出力されたパスに置き換える（差分ファイルのパスも同じ）

## Phase 3: 統合してレポートを出す

どのレンズも「照らした要件」を「なし」と返したら、範囲ごとの文言で出力して終了する。

| 範囲     | 出力                                                                                                 |
| -------- | ---------------------------------------------------------------------------------------------------- |
| 今の差分 | 「照らす要件なし（差分が触れる規則が要件定義書に見つかりませんでした）」と、差分の対象ファイルの一覧 |
| 機能名   | 「照らす要件なし（機能『<引数の文字列>』の規則が要件定義書に見つかりませんでした）」                 |
| 全部     | 「照らす要件なし（要件定義書に規則が見つかりませんでした）」                                         |

それ以外は、[`.claude/rule-bodies/review-integration.md`](../../rule-bodies/review-integration.md) を Read し、その手順に従う。この Skill が変える内容は次のとおり。

- **手順1の代わり**：引用の無い指摘だけを落とし、引用が差分の行に無いことでは落とさない。引用は、要件の原文と欠落を確かめた範囲の2つで、どちらかが無い指摘を落とす（落とす例：要件の原文はあるが、欠落を確かめた範囲の欄が無い。残す例：欠落を確かめた範囲が、探したテストファイルの一覧のパスになっている）。この Skill の指摘はテストの欠けか、要件と食い違う期待値で、差分の外の既存テストにもあるので、差分の行を引用できるとは限らない。共通の手順1のまま差分で絞ると、指摘がほとんど残らない
- **照らした要件を集める**：各レンズの「照らした要件」を、重なる行を1つにまとめてレポートの「照らした要件」欄へ移す。照らした要件を見せるのは、照らす規則を agent が選ぶので、選び漏れを人間が見つけられるようにするためである

出力は `references/report-format.md` の書式に従う。
