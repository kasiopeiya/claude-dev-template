テストを要件定義書の規則に照らしてレビューしてください。あなたはレビュー本体を行わず、**`test-spec-reviewer-agent` を走らせ、返ってきた結果を統合する**役です。

判定する範囲は今の差分です。差分は照らす規則を決めるためだけに使い、その規則のテストの欠けは、差分の前からあるものも出します。

`test-spec-reviewer-agent` は Bash を持たないので、差分とテストファイルの一覧は、あなたが取ってファイルに書き、そのパスを渡します。

## なぜ `/code-review` のレンズにしないか

`/code-review` は、差分か渡したパスの `.ts`・`.tsx` ファイルを対象に始まる。このレビューの単位は要件定義書の規則で、規則のテストは差分の外の既存のテストファイルにもある。対象の集合が違うので、review-subagent-lens-policy「対象の集合が違う観点は、取りこぼしを待たずに分けてよい」に従い、別の Skill と agent にした。`/code-review` のレンズに足すと、差分の外の追跡済みテストファイルまで集めて渡す手順を、ほかのレンズは使わない。既存のテストレンズに足すと、対象の集合が違う観点を既存レンズに混ぜることになる。`code-reviewer-agent` を流用すると、TypeScript コード用の agent に要件定義書を読む役が混ざる。

## Phase 1: 要件定義書と対象を決める（1回だけ）

### 要件定義書を確かめる

`docs/requirements.md` が無ければ、「照らす要件なし（docs/requirements.md がありません）」と出力して終了する。中身が見出しだけかどうかは、ここでは判定しない（agent が照らす規則を探し、無ければ「照らした要件」を「なし」と返す）。

### 差分の対象を集める

Bash で `git diff HEAD --name-only --diff-filter=ACMR`（未コミットの変更）と `git ls-files --others --exclude-standard`（未追跡の新規ファイル）を実行して結合し、重複を除いた中から `.ts`・`.tsx` で終わるファイルを集める。要件定義書などの `.md` は含めない（規則を書いた側の変更は、テストが触れた規則ではない）。

0件なら「差分に .ts・.tsx のファイルがありません」と出力して終了する。

### 差分ファイルとテストファイルの一覧を書く

追跡済みの対象の差分と、テストファイルの一覧を、`tmp/`（git 管理外）配下に書く。コマンドは1本ずつ分けて打つ。worktree に入ったセッションでは、git を含む複合コマンドが止められるためである。まず書き先を作る。

```bash
dir=tmp/test-spec-review/$(date +%Y%m%d-%H%M%S) && mkdir -p "$dir" && echo "$dir"
```

出力されたパスを、以下の `<dir>` にそのまま書く（シェル変数は Bash ツールの呼び出しをまたいで残らない）。追跡済みの対象ごとに1本、差分を書く。

```bash
git diff HEAD -- <パス> > <dir>/<パスの / を __ にした名前>.diff
```

テストファイルの一覧を、2本で書く。

```bash
git ls-files '*.test.ts' '*.test.tsx' '*.spec.ts' '*.spec.tsx' > <dir>/test-files.txt
git ls-files --others --exclude-standard '*.test.ts' '*.test.tsx' '*.spec.ts' '*.spec.tsx' >> <dir>/test-files.txt
```

テストファイルの一覧は、差分のテストだけでなく、追跡されたテストファイル全体にする。差分のファイルだけを渡すと、規則のテストが既存のファイルにあっても見えず、「テストが無い」と過検知する。`.test.mjs` は含めない（このリポジトリではハーネスのスクリプトのテストで、プロダクトの要件を確かめるものではない）。

未追跡の新規ファイルは差分ファイルを書かない（全行が追加行なので、agent は対象ファイルを読めば足りる）。

## Phase 2: レンズを起動する

`.claude/agents/test-spec-reviewer-agent/test-spec-reviewer-agent.md` の「レンズ一覧と担当観点（正典）」を Read し、レンズごとに1回ずつ、**1メッセージ内でまとめて** `test-spec-reviewer-agent` を Task 起動する。

各起動には次を渡す。差分の中身はプロンプトに書き写さない。

- **レンズ名**：正典の表記のまま
- **要件定義書のパス**：`docs/requirements.md`
- **差分の対象ファイルの一覧**：各ファイルのパスと、差分ファイルのパス（書いたものだけ）
- **テストファイルの一覧のパス**：Phase 1 のコマンドが最後に出力したディレクトリ（`tmp/test-spec-review/<日時>`）の `test-files.txt`。`$dir` のまま渡さず、出力されたパスに置き換える（差分ファイルのパスも同じ）

## Phase 3: 統合してレポートを出す

どのレンズも「照らした要件」を「なし」と返したら、「照らす要件なし（差分が触れる規則が要件定義書に見つかりませんでした）」と、差分の対象ファイルの一覧を出力して終了する。

それ以外は、[`.claude/rule-bodies/review-integration.md`](../../rule-bodies/review-integration.md) を Read し、その手順に従う。この Skill が変える内容は次のとおり。

- **手順1の代わり**：引用の無い指摘だけを落とし、引用が差分の行に無いことでは落とさない。引用は、要件の原文と欠落を確かめた範囲の2つで、どちらかが無い指摘を落とす（落とす例：要件の原文はあるが、欠落を確かめた範囲の欄が無い。残す例：欠落を確かめた範囲が、探したテストファイルの一覧のパスになっている）。この Skill の指摘はテストが無いことなので、差分の行を引用できない。共通の手順1のまま差分で絞ると、指摘が1件も残らない
- **照らした要件を集める**：各レンズの「照らした要件」を、重なる行を1つにまとめてレポートの「照らした要件」欄へ移す。照らした要件を見せるのは、照らす規則を agent が選ぶので、選び漏れを人間が見つけられるようにするためである

出力は `references/report-format.md` の書式に従う。
