# レビューレポートフォーマット

点数・レベル・良い点は、どの欄にも書かない。結果を使う側（/cdk-dev など）は指摘の有無と severity だけで直すかを決めており、良い点を求めると、見る観点の少ないレビューでは良い点のでっち上げを招く。

## 個別ファイルレポート

```
## CDK Code Review Report

### 📁 ファイル情報
- ファイル: [ファイルパス]
- 種別: [App / Stack / Construct / Parameter]
- 最終更新: [git log による最終コミット日時]

### 📋 観点ごとの判定

<!-- cdk-reviewer-agent.md「レビュー観点」の TypeScript 共通観点・CDK 固有観点を上から順に全行書き出す（行を省かない）。観点名は一覧の行名と一字一句同じにする -->

| 観点 | 判定 | 指摘の数 |
| --- | --- | --- |
| [観点一覧の行名] | [準拠 / 違反 / 対象外 / 未判定] | [違反なら件数、それ以外は -] |

### 🏗️ CDK リソース情報
- Construct 数: X
- Lambda 関数: X
- S3 バケット: X
- DynamoDB テーブル: X
- その他のリソース: X

### 🔧 改善が必要な点

#### 🚨 Critical
<!-- 各指摘は「場所・引用・提案・理由」の4点を必ず書く。引用を示せない指摘は書かない -->

- **[観点名]**: [セキュリティリスク・データ損失リスクの重大な問題など]
  - **場所**: [ファイルパス:行番号]
  - **引用**: [対象ファイルからコピーしたコード1〜3行。欠落の指摘なら、欠落を確認した範囲のコード]
  - **提案**: [改善後のコード例]
  - **理由**: [なぜこの改善が必要か]

#### ⚠️ High
- **[観点名]**: [CDK ベストプラクティス違反・保守性の問題など]（場所・引用・提案・理由は Critical と同じ4点を書く）

#### 💡 Medium
- **[観点名]**: [命名・コメント・スタイル改善など]（場所・引用・提案・理由は Critical と同じ4点を書く）

#### ❓ 確認点（Review Questions）
<!-- 観点一覧の外。設定値の妥当性・運用への影響など、実装者に念のため確認しておきたいポイント -->
<!-- 例: ログ保存期間が1ヶ月で要件に合っているか、RemovalPolicy.DESTROYがデータ保護の観点で問題ないか、など -->

- **[確認したい観点]**: [具体的な確認内容]
  - **場所**: [ファイルパス:行番号]
  - **現状**: [現在の設定や実装]
  - **確認事項**: [何を確認してほしいか・どのような懸念があるか]

### 📏 CDK ルールへの準拠

<!--
次の順で書く（省略不可）。項目は `.claude/rules/cdk.md` を SSOT とし、ここに転記しない。
1. その SSOT を Read し、「CDKの差分検知ルール」以外の `##` 見出しを上から順に全部書き出す。
2. 各節のルールを項目単位（箇条書き1行・表1行が1項目）に分け、✅/⚠️/❌ + 詳細 で列挙する。違反なしでも ✅ で証跡を残す。
3. 出力前に、1 で書き出した見出しが全て 2 に現れているか数えて確かめる。
-->
- ✅ / ⚠️ / ❌ [cdk.md のルール]: [詳細]

**差分検知ルール（違反は原則 Critical）**

<!--
cdk.md「CDKの差分検知ルール」配下の `###` 見出し（DON'T / MUST）を上から順に全部書き出し、1つずつ ✅/⚠️/❌ + 詳細 で列挙する。
複数の見出しを1行にまとめない——まとめると、照合したのか落としたのかを読者が区別できない。
出力前に、書き出した見出しの数と列挙した行数が一致するか数えて確かめる。
-->

- ✅ / ⚠️ / ❌ [cdk.md の差分検知ルール]: [詳細]

### 🚀 次のステップ（優先度付き）

<!-- 優先度は指摘の severity から決める（Critical→高・High→中・Medium→低） -->

1. [最優先で修正すべき項目]
2. [次に修正すべき項目]
3. [時間があれば改善したい項目]
```

```
### ファイル別指摘件数
| ファイル | 種別 | Critical | High | Medium |
|---------|------|----------|------|--------|
| [パス]  | Stack | [件数]  | [件数] | [件数] |

### 🚦 合否

<!--
合否の判定基準は ai-review-gate-policy（../../../../docs/policy/ai-review-gate-policy.md）「合格条件は『残してよい2種類以外のCriticalが0件』」。
コード・設計書レビューを通じた Critical の合計から、issue:needs-human-decision として起票した件数を引いたもので判定する。
-->

- **判定**: [🚫 要修正 / ✅ 合格]
- **Critical残数**: [上の計算による件数]
- **Issue にして残す Critical**: [issue:needs-human-decision として起票した Issue 番号と概要。無ければ「なし」]

### 全体の次のステップ
[プロジェクト全体で取り組むべき優先タスク]
```
