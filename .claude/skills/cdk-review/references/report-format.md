# レビューレポートフォーマット

## 個別ファイルレポート

```
## CDK Code Review Report

### 📁 ファイル情報
- ファイル: [ファイルパス]
- 種別: [App / Stack / Construct / Parameter]
- 最終更新: [git log による最終コミット日時]

### 📊 総合評価
- 得点率: XX%（合計得点 ÷（適用観点数 × 3））
- レベル: [優秀 (90%+) / 良好 (70-89%) / 要改善 (50-69%) / 要リファクタリング (50%未満)]

### 🏗️ CDK リソース情報
- Construct 数: X
- Lambda 関数: X
- S3 バケット: X
- DynamoDB テーブル: X
- その他のリソース: X

### ✅ 良い点（最低3つ）
- [具体的な良い点]

### 🔧 改善が必要な点

#### 🚨 必須（Critical）
- [セキュリティリスク・型安全性の重大な問題など]

#### ⚠️ 推奨（Recommended）
- [CDK ベストプラクティス違反・保守性の問題など]

#### 💡 提案（Suggested）
- [命名・コメント・スタイル改善など]

#### ❓ 確認点（Review Questions）
<!-- スコア対象外。設定値の妥当性・運用への影響など、実装者に念のため確認しておきたいポイント -->
<!-- 例: ログ保存期間が1ヶ月で要件に合っているか、RemovalPolicy.DESTROYがデータ保護の観点で問題ないか、など -->

- **[確認したい観点]**: [具体的な確認内容]
  - **場所**: [ファイルパス:行番号]
  - **現状**: [現在の設定や実装]
  - **確認事項**: [何を確認してほしいか・どのような懸念があるか]

### 📏 CDK ルールへの準拠

<!-- .claude/rules/cdk.md の「CDKの差分検知ルール」以外の各ルールを1項目ずつ照合し、✅/⚠️/❌ + 詳細 で列挙する。違反なしでも ✅ で証跡を残す。項目は cdk.md を SSOT とし、ここに転記しない -->
- ✅ / ⚠️ / ❌ [cdk.md のルール]: [詳細]

**差分検知ルール（違反は原則 Critical）**

<!-- cdk.md「CDKの差分検知ルール」配下の DON'T / MUST を1項目ずつ照合し、同じ形式で列挙する -->

- ✅ / ⚠️ / ❌ [cdk.md の差分検知ルール]: [詳細]

### 🚀 次のステップ（優先度付き）

1. [最優先で修正すべき項目]
2. [次に修正すべき項目]
3. [時間があれば改善したい項目]
```
