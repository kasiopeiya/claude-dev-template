# CDK コードレビュー観点

CDK コードレビューを行う AI・人間が、どの観点を見て、何を違反とするか迷ったときに引く観点一覧。

観点ごとに **準拠／違反／対象外** を判定し、違反は「severity の決め方」に従って severity 付きの指摘にする。点数は付けない。

> [!IMPORTANT]
> **（AI・必須）** 観点一覧の行は能動的に探す対象＝レビューの背骨である。ここには**機械（ESLint/knip）で測れない判断項目だけ**を載せる。機械化できない判断項目は一覧の行にしないと素通りするため、行にすることが品質の生命線となる。

下の観点一覧の観点は**観点名で識別する**（他ドキュメントからも観点名で参照する）。番号を振ると、観点の増減で番号がずれ、参照側が無言で壊れるためである。

## CI ゲートで機械的に担保される観点（判定対象外）

次の観点は ESLint / knip が **error で機械的に検知**するため、LLM の判定から外す（CI ゲートを SSOT とし、二重に判定しない）。設定の実体は `eslint.config.mjs` / `knip.jsonc` を参照。

- **型安全性（`any` 禁止）**：ESLint `@typescript-eslint/no-explicit-any`
- **未使用の引数（optional 含む）**：ESLint `@typescript-eslint/no-unused-vars`（`args:'all'`）
- **不要な export（本番コードからも未参照）**：knip（未使用 export 検知）。テストからのみ参照される export は検出しないため、下の観点一覧「テスト専用 export」で見る
- **Import 順序・冒頭集約**：ESLint `import-x/order` / `import-x/first`
- **Import 形式（aws-cdk-lib の barrel 形式）**：ESLint `local/aws-cdk-lib-barrel-import`

未使用の `private` フィールドは ESLint では落ちず、CDK の CI（`ci-cdk` ジョブ）は型検査を走らせないため、観点一覧「未使用のインスタンス変数」で見る。

## 判定方針

- **違反**：観点の「違反と判定する条件」に当たる箇所を引用できたとき。違反ごとに指摘を1件出し、下の「severity の決め方」で severity を付ける
- **準拠**：その観点を探した結果、条件に当たる箇所が無かったとき。「おそらく問題ない」という印象で付けない
- **対象外**：観点の注記が対象外と定める場合、または観点が見る対象（該当するリソース種別・記述）がそのファイルに1つも無い場合に使う（例：Stateful リソースが無いファイルの RemovalPolicy、自作 Construct を定義しないファイルの Construct ID 規則）
- **疑わしい場合に違反側へ倒すのは、引用は取れるが解釈が分かれるときだけ**。その場合は指摘に「解釈が分かれる（引用箇所を〇〇と読むなら違反）」と明記する。**引用そのものが取れない「確認が取れない」は違反にしない**——それはコードの欠陥ではなく、こちらが読み切れていないだけかもしれない

## 観点一覧

| 観点                         | チェック内容                                                                                                                                                                                                             | 違反と判定する条件                                                                                                                                                      |
| ---------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **型アサーションの乱用**     | 型アサーション（`as`・非 null アサーション `!`）で型検査を黙らせていないか                                                                                                                                               | 理由のコメントが無い型アサーションがある                                                                                                                                |
| **命名規則・変数名の妥当性** | Construct ID・変数名に一貫性があり、意図が明確か。汎用的すぎる名前（❌ `bucket` ⭕ `webSiteBucket`）になっていないか                                                                                                     | 用途が名前から読み取れない、不適切な命名がある、または汎用的すぎて用途が読み取れない変数名がある                                                                        |
| **コメント**                 | `docs/policy/code-comment-policy.md` に準拠しているか（SSOT。実装コメントは WHY のみ）。コードを読めば自明な内容を説明するだけのコメント（例: `// スタック削除時にテーブルも削除` + `RemovalPolicy.DESTROY`）が無いか    | WHY コメントが必要な箇所に無い、ポリシーに反するコメントがある、または自明なコードへの説明コメントがある                                                                |
| **エラーハンドリング**       | 必須の環境変数・context 値・props が欠けたとき、Synth 時に明示的なエラーで止まるか（型で必須にできるものは対象外。ランタイムの外部入力に限る）                                                                           | 欠けた状態のまま Synth が通り、意味不明なエラーや意図しない構成で後工程まで進む箇所がある                                                                               |
| **セキュリティ**             | セキュリティリスクがないか（ハードコード・環境変数の非 null 断定 `process.env.X!` を含む）                                                                                                                               | セキュリティリスクがある（実害に直結するものは Critical）                                                                                                               |
| **未使用のインスタンス変数** | `private readonly` フィールドがコンストラクタ外で参照されているか                                                                                                                                                        | 参照されない `private readonly` フィールドがある                                                                                                                        |
| **テスト専用 export**        | 本番コードからは参照されず、テストからだけ import されている `export` がないか                                                                                                                                           | テストからだけ import される export がある                                                                                                                              |
| **不要なpublic公開**         | クラス外から参照されないメンバ変数・メソッドに `public` が付いていないか。CDK の Stack/Construct が他の Stack/Construct から参照されるプロパティ、`bin/` からインスタンス化される Stack は external usage ありと判断する | クラス外から参照されない public メンバがある                                                                                                                            |
| **単一責任**                 | Construct/Stack が単一責任を遵守しているか                                                                                                                                                                               | 複数のドメインの責任をまとめて持っている                                                                                                                                |
| **重複コード**               | 同じパターンの Construct 定義が複数回出現していないか                                                                                                                                                                    | props の組がほぼ同じ Construct/Stack 定義が3回以上あり、共通化すれば差分が引数だけになる                                                                                |
| **宣言的記述**               | `if`/`switch` などの制御構文に頼らず宣言的に書けているか                                                                                                                                                                 | 環境の切り替え以外の目的で、`if`/`switch` がリソースの有無・構成を分けている（環境ごとの値の選択・切り替えは対象外）                                                    |
| **L2 Construct 優先**        | L2 Construct を優先しているか。L1（`Cfn*`）使用時は理由がコメントにあるか                                                                                                                                                | 理由の記載が無い L1 Construct の使用がある                                                                                                                              |
| **IAM 自動生成活用**         | `grant*` メソッドを活用し、明示的な Role/Policy 定義を避けているか                                                                                                                                                       | `grant*` で代替できるのに明示的な Role/Policy を定義している（過剰な権限になるものは Critical）                                                                         |
| **RemovalPolicy**            | Stateful リソース（S3・DynamoDB 等）に `RemovalPolicy` が設定され、`DESTROY`/`RETAIN` の選択がデータ保護の観点から適切か                                                                                                 | Stateful リソースに `RemovalPolicy` が未設定（本番データを扱うものは Critical）、または選択が意図しないデータ削除・残留につながる（例は下の「RemovalPolicy の判定例」） |
| **Construct ID 規則**        | 自作 Construct 内のメインリソース ID が `Resource` または `Default` か                                                                                                                                                   | 規則に反する Construct ID がある                                                                                                                                        |
| **スタック分割の適切さ**     | デプロイ単位として適切に分割されているか                                                                                                                                                                                 | 分割が不適切（デプロイ単位・変更頻度が混在している等）                                                                                                                  |
| **循環参照の検出**           | リソース間の依存関係（参照・権限付与）に循環（A→B→C→A）がないか                                                                                                                                                          | 循環参照がある（`cdk synth`/`deploy` が失敗しうるため Critical）                                                                                                        |
| **CDK設計ポリシー準拠**      | `docs/policy/cdk-design-policy.md` の「レビュー観点（チェックリスト）」に準拠しているか。**判定基準は同ポリシーを唯一の正典（SSOT）とし本表には転記しない**                                                              | ポリシーに反する箇所がある                                                                                                                                              |
| **CDK差分検知ルール準拠**    | `.claude/rules/cdk.md`「CDKの差分検知ルール」節に準拠しているか。**判定基準は同節を唯一の正典（SSOT）とし本表には転記しない**                                                                                            | 節に反する箇所がある（`cdk diff` が変更を正しく示さず、デプロイ事故・データ損失につながるため Critical）                                                                |

### RemovalPolicy の判定例

- **削除の例（違反）**：本番のユーザーデータを持つテーブル・バケットが `removalPolicy: RemovalPolicy.DESTROY` になっている
- **残留の例（違反）**：開発環境だけで使う一時バケットが `RETAIN` になっていて、スタックを消しても残り、次のデプロイで物理名がぶつかる
- **当たらない例（準拠）**：環境ごとに props で切り替えていて、本番では `RETAIN` になる。または一時データ用で、`DESTROY`＋`autoDeleteObjects: true` の理由がコメントにある

## severity の決め方

重大度（Critical / High / Medium）の定義は [ai-review-gate-policy](../../../../docs/policy/ai-review-gate-policy.md) が正典。CDK レビューでは次のように当てる。観点の「違反と判定する条件」に severity の指定があるときは、そちらに従う。

- **Critical**：放置するとデプロイ失敗・セキュリティ事故・データ損失につながる（循環参照、過剰な IAM 権限、本番データを扱う Stateful リソースの RemovalPolicy 未設定、CDK 差分検知ルール違反など）
- **High**：いまは動くが、変更や保守の際に壊れやすい（CDK ベストプラクティス・ポリシーの違反など）
- **Medium**：読みやすさ・分かりやすさの改善（命名・コメントの軽微なゆらぎなど）

## 観点一覧の外の確認点（確認点として報告）

観点一覧の判定には含めない（違反・severity を付けない）。担当レンズが必ず確認し「確認点」として報告する。コード内に該当サービスが存在する場合、下の表の設定項目を確認し、ベストプラクティスから外れている・一般的でない設定は「確認点」として報告する。明らかな欠陥（公開設定の欠落・暗号化なしなど）は観点「セキュリティ」「IAM 自動生成活用」等が違反として拾う。

### サービス設定値（セキュリティ）

| サービス              | 確認する設定項目                                                                                                                                                                                                                                 |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **S3**                | `blockPublicAccess`（`BLOCK_ALL` 推奨）・`encryption`（`S3_MANAGED` 以上を推奨）                                                                                                                                                                 |
| **CloudFront**        | `minimumProtocolVersion`（`TLS_V1_2_2021` 推奨）・`geoRestriction`（要件に応じて設定）                                                                                                                                                           |
| **Cognito User Pool** | `passwordPolicy`（最小8文字・大小英数字記号を含む）・`mfa`（`REQUIRED`/`OPTIONAL` 推奨）・`advancedSecurityMode`（`ENFORCED` 推奨）・トークン有効期限（`accessTokenValidity`/`idTokenValidity`/`refreshTokenValidity` がデフォルト放置でないか） |
| **DynamoDB**          | `encryption`（`AWS_MANAGED` 以上を推奨）                                                                                                                                                                                                         |
| **Lambda**            | `environment`（シークレット値を直接渡さず Secrets Manager / Parameter Store を使用すべき）                                                                                                                                                       |
| **API Gateway**       | CORS（`allowOrigins: ['*']` になっていないか、必要最小限のオリジンを許可）                                                                                                                                                                       |

### サービス設定値（運用・性能）

| サービス        | 確認する設定項目                                                                                                                                                        |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Lambda**      | `memorySize`（512MB〜推奨）・`timeout`（デフォルト3秒放置になっていないか）・`logRetention`（`INFINITE`/未設定を避ける）・`runtime`（EOL 済み・非推奨になっていないか） |
| **S3**          | `versioned`（重要データは `true` 推奨）・`lifecycleRules`（不要オブジェクトの自動削除）                                                                                 |
| **CloudFront**  | `httpVersion`（`HTTP2`/`HTTP2AND3` 推奨）・`enableLogging`（本番環境では有効化推奨）                                                                                    |
| **DynamoDB**    | `pointInTimeRecovery`（本番データでは `true` 推奨）・`billingMode`（アクセスパターンに応じた選択か）                                                                    |
| **API Gateway** | スロットリング（`defaultThrottle` で上限を設定）・アクセスログ（有効化推奨）                                                                                            |

## 種別ごとの重点観点

観点名は上の「観点一覧」の行名と完全に一致させる。渡された種別（App / Stack / Construct / Parameter。判定は `/cdk-review` の SKILL.md「種別を決める」が SSOT）に応じて、次の観点から先に、時間をかけて見る。

- **App**：CDK差分検知ルール準拠・スタック分割の適切さ
- **Stack**：RemovalPolicy・スタック分割の適切さ・循環参照の検出
- **Construct**：L2 Construct 優先・Construct ID 規則・重複コード
- **Parameter**：型アサーションの乱用・セキュリティ
