# エラーハンドリング・制約事項・実装上の注意点

`/cdk-imp` の実行中にエラーへ突き当たったとき、または実装方針の制約を確認したいときに読む。

## エラーハンドリング一覧

| エラー種別                   | 判定方法                                      | 処理内容                                                                |
| ---------------------------- | --------------------------------------------- | ----------------------------------------------------------------------- |
| Issue が見つからない         | gh issue view がエラー                        | エラーメッセージを表示し再入力を促す（最大3回）                         |
| Issue の body が空           | JSON body フィールドが空                      | 処理を中止                                                              |
| 設計書ファイルが見つからない | Read でエラー                                 | 警告を表示し、Issueの情報のみで処理継続                                 |
| npm test 失敗                | 終了コード 非0                                | エラーメッセージを解析し、修正方法を提案                                |
| スナップショット不一致       | テストエラーメッセージに "snapshot" 含む      | AskUserQuestion でスナップショット更新の可否を確認                      |
| cdk synth 失敗               | 終了コード 非0                                | エラーメッセージを解析し、修正方法を提案                                |
| 循環参照エラー               | エラーメッセージに "Circular dependency" 含む | 原因リソースを特定し、回避方法を提案（SSM/ワイルドカード/L1 Construct） |
| 修正試行回数超過             | 3回連続で同じエラー                           | 処理を中止し、ユーザーに手動修正を促す                                  |

同じエラーで3回連続失敗した場合は処理を中止する。無限ループを避け、ユーザーに手動修正を促す。

## 制約事項

| 対象                 | 制約                                                                             |
| -------------------- | -------------------------------------------------------------------------------- |
| TypeScriptコンパイル | `tsc` は実行しない。型エラーは `npm test` または `cdk synth` で検出される        |
| デプロイ             | `cdk deploy` は実行しない。デプロイは人間が実施する                              |
| スタック構成         | 単一・複数いずれの構成もありうる。スタック数・分割方針はインフラ設計書を確認する |

## 循環参照の回避

CloudFormation の循環参照は次のパターンで起きやすい。回避方法はパターンごとに決まる。

| 循環するリソース                 | どう循環するか                                                                                     | 回避方法                         |
| -------------------------------- | -------------------------------------------------------------------------------------------------- | -------------------------------- |
| CloudFront ⇔ Lambda Function URL | CloudFront が Lambda URL を Origin として参照し、Lambda の IAM ポリシーが CloudFront の URL を参照 | SSM Parameter Store 経由にする   |
| Lambda ⇔ DynamoDB                | Lambda が DynamoDB テーブルを参照し、DynamoDB ストリームが Lambda を参照                           | IAM ポリシーをワイルドカード指定 |
| S3 ⇔ CloudFront                  | S3 バケットポリシーが CloudFront の OAC を参照し、CloudFront が S3 を Origin として参照            | L1 Construct（Cfn）で後付けする  |

## スナップショット更新のタイミング

次のいずれかに当たるとき、スナップショットの更新が要る。ユーザーに確認したうえで `npm test -- -u` を実行する。

- 新規リソース追加
- リソースプロパティ変更
- CloudFormationテンプレート構造変更
