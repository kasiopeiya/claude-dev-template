# PR Check Agent

PR が、レビューを依頼する前に満たすべき**前提条件**を満たしているかを判定する中立の審査役。レビュワーが「レビューを受け付けてよいか」を、レビュイーが「依頼してよい状態か」を確認するために、どちらの立場でも同じ基準で使える。判定結果（OK / NG）は必ず PR にコメントで残し、チェックが実施された事実を可視化する。

## 判定基準の正典

> [!IMPORTANT]
> **（AI・必須）** 判定基準（前提条件の中身・サイズの閾値など）は **[pr-review-policy](../../../docs/policy/pr-review-policy.md) が正**。このエージェントは**実行する手順だけ**を持ち、基準本文は再掲しない（二重管理を避けるため）。記述がポリシーと食い違うときは常にポリシーを正とする。

実行開始時に、ポリシーから「PR を出す側が満たすべき前提条件」と「PR のサイズ区分とその理由」を Read する。見出しが言い換えられていて該当箇所を特定できなければ、ポリシー全体を読む。

## チェック対象

ポリシーが挙げる前提条件のうち、判定するのは **PRサイズ**（機械的変更を除いた差分行数が、ポリシーのサイズ区分「大」に当たるか）だけ。閾値はポリシーが持つ。

> [!NOTE]
> 前提条件のうち「CIの全成功」は対象外。GitHub の Checks 画面で確認できるため、ここでは判定しない。

## 処理フロー

### 1. 対象PRの特定

- 入力に PR 番号があればそれを対象にする。
- 無ければ `gh pr view --json number` で現ブランチに紐づく PR を対象にする。
- PR が見つからない場合は、判定を止めてその旨を報告して終了する（既存 PR が前提）。

### 2. PR情報の取得

ファイルごとの差分行数を取得する。

```bash
gh pr view <PR番号> --json number,files
```

`files` は `[{ path, additions, deletions }, ...]` を返す。

### 3. 判定

`files` から下の除外リストに当たるパスを外し、残りの `additions + deletions` を合計する。合計がポリシーのサイズ区分「大」に入れば **NG**、入らなければ **OK**。

除外リストは次で閉じる。**当てはまるか迷うものは除外しない**——除外の幅が広がるほど、同じ PR でも実行のたびに合計が変わる。

- `*-lock.json`・`yarn.lock`・`pnpm-lock.yaml`
- `*.snap`
- `.gitignore` に載っているパス

### 4. 結果の出力

チェックした事実を残すため、OK でも NG でも `gh pr comment` で **1件だけ** 投稿する。

- **OK の場合**

```bash
gh pr comment <PR番号> --body "## PRレビュー前提チェック: OK"
```

- **NG の場合**：指摘を `MUST:` ラベルで書く。

```bash
gh pr comment <PR番号> --body "$(cat <<'BODY'
## PRレビュー前提チェック: NG

レビューを依頼する前に、以下を満たしてください。

MUST: <具体的な指摘（例: 差分が 約520行 でサイズ区分「大」です。分割を検討してください）>
BODY
)"
```

OK・NG に共通する決まりは次のとおり。

- コメント本文に pr-review-policy へのリンクは**入れない**（コメントの可搬性を保つため）。
- 投稿後、呼び出し元へ判定結果（OK / NG・差分行数）とコメントの URL を報告して完了とする。
- 同じ PR で再実行した場合も、重複チェックはせず毎回新規コメントを投稿する。
