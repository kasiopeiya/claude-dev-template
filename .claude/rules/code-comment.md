# コードコメントの記法

コメントの**思想**（種類ごとに何を書くか）は [code-comment-policy.md](../../docs/policy/code-comment-policy.md) が定める。ここでは、それを踏まえた**書き方（How）**だけを定める。

## 対象読者

AIエージェントが、コードコメントを実装・レビューし、`@throws` のタグ書式・ファイル冒頭コメントの装飾可否・重要箇所バナーの記法・TODO/FIXMEの書き方に迷ったとき。

> [!NOTE]
> 本ページの記法のうち、`@throws`・重要箇所バナー・TODO/FIXME はESLint `local/code-comment-notation` がガードレール化済み。対象は `**/*.ts`・`**/*.tsx`・`**/*.mjs`。`.github/workflows/*.yml` はESLintの対象外のため、編集時に自分でこのページの記法に沿っているか確認する。

## `@throws` はタグ名と型を守って書く

例外は型シグネチャに現れないため、doc comment が唯一の契約になる。タグの書き方は次のように決める（どの例外を書くか＝呼び出し側が対処すべきものだけ、という線引きは code-comment-policy.md が定める）。

| 論点       | 立場                                        | 理由                                                              |
| ---------- | ------------------------------------------- | ----------------------------------------------------------------- |
| タグ名     | `@throws` を使う（`@exception` は使わない） | JSDoc/TSDoc・Javadoc 共通で通りが良く、ツールの既定               |
| 型を書くか | 書く（`@throws {ValidationError} 説明`）    | 呼び出し側は `instanceof` で catch を絞るため、型がないと書けない |

複数ある場合は1行1タグで並べる。ESLintが `@exception` タグを検出したら `@throws` に直す。型無しの `@throws` を検出したら、呼び出し側が対処すべき例外（code-comment-policy.md 参照）なら型を付けて `@throws {型} 説明` の形に直し、対処不要な例外（実装の都合で漏れるだけのもの）ならタグごと消す。

```typescript
/**
 * 請求金額を計算する。
 *
 * @throws {ValidationError} 明細が空のとき
 * @throws {TaxRateNotFoundError} 適用する税率が未登録のとき
 */
```

## ファイル冒頭コメントは装飾しない

通常のコメント（`//` または先頭の doc comment）で書き、罫線・枠は付けない。装飾付きの区切り線は次の「重要箇所バナー」専用の記法であり、混ざると信号にならない。

```typescript
// 責務: OAuth の state パラメータの生成と検証のみを担う
```

- ❌ `// ═══…` の罫線で挟んで飾る → ✅ 罫線を付けず通常のコメントで書く

## 重要箇所バナーは打つなら心臓部に1個だけ

バナーは任意。名前と位置（新聞構造）だけでは心臓部が埋もれるファイルに限り、そのファイルの心臓部（最重要のビジネスロジック・`main` 等）に、読まずに目へ飛び込むバナーを打つ。重要さは第一に名前と位置で語らせ、バナーはその補助に留める。

```typescript
// ═══════════════════════════════════════════════
//  ★ このファイルの心臓部 — 課金計算ロジック
// ═══════════════════════════════════════════════
function calculateBillingAmount(invoice) {
  ...
}
```

- **1ファイルに最大1個**：希少だから信号になる。複数打つと何も目立たない。ESLintは `// ═+` の行が挟むブロックをファイル先頭から順に数える。個数超過を検出したら、まずファイル冒頭コメントの罫線（前節が禁じる装飾）を外し、それでも2個以上残るなら心臓部以外のバナーを外す
- ❌ 行末に `║` の右枠を付ける → ✅ 左の `// ═══…` 線だけにする（全角を含む右端合わせは保守地獄）。区切り線は上の例の行をそのままコピーし、長さを変えない
- **視覚マーカーであり意味タグではない**：`// CRITICAL:` のような grep 用タグとは目的が違う

## TODO / FIXME には Issue 番号を併記する

追跡先のない TODO は、いつ外すのか誰にも分からないまま腐る。外す判断を Issue へ渡し、コメントには番号だけを残す。Issue 番号のない TODO は書かない。

ESLintは `TODO`/`FIXME` の直後に `(#数字)` が続かないものを違反として検出する。番号が無ければ Issue を起票して `TODO(#番号):` にする。番号はあるが位置が違う（例：`TODO: 〜 (#42)`・`TODO #42:`）なら、起票せず番号を直後へ移す。

```typescript
// TODO(#42): バッチサイズを設定可能にする
const BATCH_SIZE = 100
```
