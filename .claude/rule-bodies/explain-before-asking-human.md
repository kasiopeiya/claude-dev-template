# 人間に判断を求める前に前提を説明する手順

このファイルを名指しした Skill は、人間に問う前にこのファイルを Read して従う。全場面に効く最小の決まりは `CLAUDE.md` の「人間に判断を求める前に、前提を説明して理解を確かめる」にあり、このファイルはその実例と、Skill が名指ししたときに行う「全体像を共有する段」を書く。食い違ったら `CLAUDE.md` を正とし、このファイルを直す。

人間が中身を分からないまま決めると、なぜそう決めたかを後から誰も説明できない。これを理解負債と呼ぶ。この手順は、理解負債を溜めないためにある。

## 置き場を選んだ理由

この手順を使う Skill は複数あり、持ち主の Skill が1つに決まらない。そのため、[policy-driven-development-policy](../../docs/policy/policy-driven-development-policy.md) の「パスで言えない How は、…Skill から直接リンクで読ませる Rule にする」に従い、Rule にする。置き場は同ポリシーの「Skill などから直接リンクで読ませる Rule は…`.claude/rule-bodies/` に置く」が決めている。`.claude/rules/` に置くと、Skill のリンクと無関係に毎回全文が読み込まれるためである。Skill の外の相談でも人間に問うので、最小の決まりだけは `CLAUDE.md` に置いている。

## 対象読者

人間に判断を求める返答を書こうとしていて、前提の説明に何をどう書くか、説明と問いをどの返答で出すかに迷った AI エージェント。

## いつ効くか

このファイルでいう「人間に判断を求める返答」は、次の形の返答のすべてをいう。Issue 番号やパスの入力を頼む問いも含む。たとえば実装する Issue の番号を聞くなら、「決めるのは、どの Issue を実装するかです。番号を `#123` の形で返してください」のように書く。

- 選択肢を並べる返答
- `AskUserQuestion` を呼ぶ返答
- 問いで終える返答（短い確認の問いも含む）

問いの重さでは分けない。分けると、短い確認の問いが外れる。どの問いに当てるかを AI の評価に任せると、評価はいつでも「この問いは軽い」に倒せるからである。

## 説明に入れること

- **何を決めるのかを、最初の1文で言う**：背景より先に置く。何を決めるための説明かを知らないと、読み手は続く説明のどこが要点か分からない
- **名前は原文のまま出し、何を指すかを一言添えて、実際の値を1つ見せる**：文書やコードにある名前は、すべて対象である。たとえば属性名・パス・ラベル名・設定項目・外部サービスの機能名。値には、名前の種類ごとに次のものを見せる
  - 属性・設定項目：取りうる値（例：`"system": "member-site"`）
  - パス：そのファイルの該当箇所の中身（例：表の行に書かれた文言）
  - ラベル名：そのラベルが付く対象（例：`eslint.config.mjs` だけを変えた PR）
  - 外部サービスの機能：その機能に入れる設定（例：送信サービスの設定に付ける名前 `member-site`）
- **選択肢ごとに何が起きるかを、同じ値の例で示す**：「厳しくする」「緩くする」のような扱いの名前で終えず、その値が来たら何が起きるかを書く

### 名前の出し方の順

原文の名前を先に出し、何を指すかの一言はその後に添える。原文を言い換えで置き換えない。

言い換え（原文の代わりに AI が作った語）には、人間の頭の中にそれに当たる像が無い。原文が無いと、文書のどの語の話かも突き合わせられない。

## 例

### 要件定義書の属性を言い換えて問うた

❌ 属性を「依頼に書かれた名前」と言い換え、値を見せずに3択を出した。

```text
依頼に書かれた名前が登録されていないとき、どう扱いますか？
1. 拒否する
2. そのまま送る
3. 送って警告する
```

「依頼に書かれた名前」が要件定義書のどの属性か、どんな値かが分からない。選択肢も扱いの名前だけで、何が起きるかが書かれていない。

✅ 何を決めるかを先に言い、属性名の原文と値を見せ、同じ値で選択肢ごとの結果を示す。

```text
決めるのは、登録されていない利用システムから送信依頼が来たときの扱いです。

要件定義書の属性「依頼元の利用システム」（送信依頼に、利用システムが自分で書く識別名）の話です。値は "system": "member-site" のように来ます。

登録されているのは member-site だけで、打ち間違えた "system": "membr-site" の依頼が来たとします。

1. 拒否する：依頼はエラーで返り、メールは送られない。利用システムの側で打ち間違いに気づける
2. そのまま送る：メールは送られる。membr-site の名前で記録され、member-site の送信件数から漏れる
3. 送って警告する：メールは送られ、運用担当に「未登録の membr-site から依頼が来た」と通知が届く

番号で答えてください。
```

### 短い確認の問いで、決めることを言わなかった

❌ パスとラベル名を、何を指すかの一言も値も添えずに並べ、何を決めるのかを言わなかった。

```text
ポリシーの cicd 行（docs/policy/pr-review-policy.md）は「静的解析の設定」と広く書いています。CI に lint の設定だけを足すと、ポリシーと CI がまたずれます。どうしますか？
```

`cicd` が何か、「静的解析の設定」が具体的にどのファイルかが分からない。決めるのが文書の文言なのか CI なのかも分からない。

✅ 決めることから始め、名前に一言添えて値を見せ、同じ値で選択肢ごとの結果を示す。

```text
決めるのは、PR ラベルの定義の文言を狭めるかどうかです。

docs/policy/pr-review-policy.md（PR レビューの決まりを書いたポリシー）の PR ラベルの表で、cicd（CI/CD の変更を示す PR ラベル）の対象は「.github/・scripts/ci/・静的解析の設定」と書いてあります。静的解析の設定とは、たとえば eslint.config.mjs です。

一方、.github/workflows/pr-ai-triage.yml（PR にラベルを付けるワークフロー）は、変わったパスが .github/ か scripts/ci/ で始まるときだけ cicd を付けます。

eslint.config.mjs だけを変えた PR が来たとします。

1. 文言を狭める（「静的解析の設定」を消す）：この PR に cicd は付かない。ポリシーと pr-ai-triage.yml の条件がそろう
2. 文言を残し、pr-ai-triage.yml の条件に eslint.config.mjs を足す：この PR に cicd が付く。pr-ai-triage.yml を直す作業が増える

番号で答えてください。
```

## 問いの出し方

- **パネルで問うなら、説明の返答を先に終える**：説明の返答を「質問があればどうぞ。無ければ『OK』と返すと選択肢を出します」で終え、返事を受けた次の返答で `AskUserQuestion` を呼ぶ。パネルが開くと、同じ返答の本文が隠れることがある。説明を読まないまま選ばれる
- **説明と問いを1つの返答にまとめるなら、文章の番号選択にする**：選択肢に `1.` `2.` と番号を振り、「番号で答えてください」と添える。本文と選択肢が同じ画面に残る
- **自分の判断で省かない**：「軽い問いだから」「前提は共有済みだから」と判断して、説明を省いたり、パネルの前で返答を区切るのをやめたりしない。この判断はいつでも満たしたと言えるので、認めると決まり全体が外れる

理解できたかは、人間の返事で確かめる。返事が質問なら答えて、問い方ごとに次のように返答を終える。

- **パネルで問う場合**：答えた返答も、上と同じ一文で終える
- **文章の番号で問う場合**：答えた後に選択肢を出し直し、上と同じ一文を添える。人間が上へ戻って選択肢を探さずに済む

## 全体像を共有する段

Skill の手順がこの段を名指ししたときに、最初の問いの前に行う。問いは全体の一部を切り出すので、全体を知らない人間には、その問いがどこの話か分からない。

部品と流れを、実際の値でたどる表か図で見せる。

| 順  | 部品               | 受け渡す値の例                                              |
| --- | ------------------ | ----------------------------------------------------------- |
| 1   | 利用システム       | 送信依頼 `{"system": "member-site", "to": "a@example.com"}` |
| 2   | 送信 API           | `member-site` が登録済みかを引く                            |
| 3   | メール送信サービス | `a@example.com` へ送る                                      |

見せたら、「質問があればどうぞ。無ければ『OK』と返すと最初の問いを出します」で返答を終える。返事を受けてから最初の問いを出す。
