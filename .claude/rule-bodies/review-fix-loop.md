# レビューと修正のループと、フェーズ出力の表示の共通手順

実装 → レビュー → 修正を自律で回す Skill（`/code-dev`・`/cdk-dev`・`/design`・`/auto-dev`）が、各フェーズの出力を表示する前と、レビューの結果を受けて直す前に、このファイルを Read して従う。合否・回数・修正範囲の条件は [ai-review-gate-policy](../../docs/policy/ai-review-gate-policy.md) が定め、このファイルはその条件を回す手順を書く。食い違ったらポリシーを正とし、このファイルを直す。

## 置き場を選んだ理由

この手順を使う Skill は複数あり、持ち主の Skill が1つに決まらない。そのため、[policy-driven-development-policy](../../docs/policy/policy-driven-development-policy.md) の「パスで言えない How は、…Skill から直接リンクで読ませる Rule にする」に従い、Rule にする。置き場は同ポリシーの「Skill などから直接リンクで読ませる Rule は…`.claude/rule-bodies/` に置く」が決めている。`.claude/rules/` に置くと、Skill のリンクと無関係に毎回全文が読み込まれるためである。

## 対象読者

各フェーズの出力をどう表示するか、またはレビュー Skill の結果を受けて、どこまで直すか、再レビューするか、次の手順へ進んでよいかに迷った AI エージェント。

## ループ

合否・再レビューの回数・修正範囲は ai-review-gate-policy に従う。Skill ごとに違う内容（再レビューする Skill・戻り先・次に進む先・足す規定）は、その Skill の `SKILL.md` に書いてある。

- 指摘があれば、severity にかかわらずすべて直す（例外は同ポリシー「直す範囲は毎回すべて」の残してよい例外だけ）。
- その回に残してよい例外以外の Critical があったときだけ、直したあと同じレビュー Skill を再実行する。**再レビューには前回の指摘を渡さない**。
  - ❌ 再レビューのプロンプトに「前回の指摘 X が直ったか確かめて」と書く
  - ✅ 前回と同じ入力で、まっさらに起動する
- レビューは同じ Skill ごとに最大2回（初回を含む）。残してよい例外以外の Critical が0件になった回で合格とし、その回に出た High・Medium もその場で直してから次へ進む。
- 上限の回のレビューで指摘が出たら、直したうえで再レビューせずに次へ進む。

## 出力の表示

`/code-dev`・`/cdk-dev`・`/design` だけに掛かる。各フェーズの出力を**そのまま全文表示**する（要約・加工・コメント追加は禁止）。

- ❌ レビュー結果の先頭に「指摘は3件でした」とまとめを足す
